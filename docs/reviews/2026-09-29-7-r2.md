## Findings
1. (Correctness) _deepseek_scores reads frozen["prompt"] twice. cmd_freeze writes the key version, not prompt (run.py 867 to 872). Every DeepSeek request would raise KeyError. Use frozen["version"]; the stub test must build frozen with the real keys.
2. (Experimental validity) The forced-OCR measurement runs through extract(..., force_ocr=True), which stops OCR at PDF_MAX_OCR_PAGES (50) and blanks the rest. CUAD contracts run to 338k characters, so a sampled long contract would report word recall depressed by truncation, not OCR. Add a max_ocr_pages parameter, pass None from the eval, record pages OCR'd against total per contract.
3. (LLM behavior) A non-transient failure on every call (401, 400) lands in result.failed, not result.stopped, so the response would be a full document of "not classified" with cost 0 and no error. When no call produced a record and result.failed is non-empty, return 502 with the first error; keep partial results otherwise. Add the test.
4. (Internal consistency) The version guard and /models need a DeepSeek version string, and the plan does not say how it is built. The validation file carries _version_tag(model_key, version, served, thresholds) = <model_id>|prompt v3 <hash>|thresholds <sha12> (run.py 517 to 522, 959). State that the service reconstructs it from frozen["model_id"], frozen["version"] and the balanced thresholds file.

No leakage: thresholds tuned and reported on validation only; extraction on validation contracts; test and shift untouched. No pre-registered rule changes. No label or legal question. No em dashes. Commands are given, not run.
