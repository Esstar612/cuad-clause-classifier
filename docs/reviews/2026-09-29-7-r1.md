## Findings
1. (Correctness, pre-registration, user decision) "Highest grid threshold with recall >= 0.90" can be higher than the Rule B threshold. That happens whenever Rule B already reaches recall above 0.90. For those labels the high-recall point would flag fewer segments than balanced.

2. (Correctness) T.model_version hashes every non-bookkeeping file in the candidate directory (transformer.py 173-182). A thresholds_high_recall.json written into models/transformer_tuned/w-lr2e-5/epoch-4/ would change the version and cause the served model to be refused.

3. (Correctness) DeepSeek failure paths:
   - Transport failures go to result.failed and budget stops to result.stopped (run.py 174-188).
   - build_frame indexes result.records[call.key] (run.py 278), so a failed call raises KeyError.
   - complete_or_exit raises SystemExit.
   - Parse failures score 0, so they look like "none". On a review page, text that was never scored would appear cleared.
   - build_calls needs seg_idx, and to_prediction_frame needs split and labels. The "synthetic frame" does not list its columns.

4. (Correctness) load_frozen, check_recipe and the version guards raise SystemExit, which is a BaseException. The planned "left out with the reason" behavior needs an explicit `except SystemExit`.

5. (Correctness) SERVICE_DEVICE is not wired to anything. Two related problems in predict_proba:
   - warm=True runs a warm-up on every call.
   - An empty text list crashes during the warm-up. segment_text returns [] for blank input.

6. (Correctness, consistency) PDF extraction:
   - extract() has no way to force OCR, yet extraction_eval forces OCR on 10 contracts.
   - A malformed or encrypted PDF raises in pypdf and would return a 500.
   - If Tesseract is missing, the forced-OCR measurement would report skipped pages instead of refusing to run.

7. (Correctness) The high-recall reporting has two problems:
   - The code returns the pooled recall for every pooled label, so "labels below target" is wrong for pooled labels.
   - With positives == 0, it falls back to 0.01, which flags everything in that column.

8. (Leakage guard) high_recall does not check that each validation parquet comes from the served model version and the validation segments. transformer_tuned.select() does this check (lines 211-216).

9. (Budget, user decision) The Ledger supports the proposed separate path and cap. Two gaps remain:
   - Ledger reads prior_total once, at construction. Separate per-request instances, or several uvicorn workers, can each pass the cap check at the same time.
   - No per-request cap is set.

   Also, service spend sits outside the $150 hard cap "across all LLM runs" (config.py 126).

10. (Pre-registration ambiguity) The extraction measurement leaves several points open:
    - The gold-text path must be scored the same way as the extracted path. The validation parquet drops excluded segments (build_segments.py 39-44).
    - The source of the gold contract labels is not named.
    - The difference interval should use a paired bootstrap on shared resample_weights.
    - Ten OCR contracts are too few for an interval.

11. (CLAUDE.md, core logic) The DeepSeek service path (ledger and rate limits), the extraction metrics and bootstrap, and the OOV percentile are core logic, and the plan does not show them.

12. (CLAUDE.md, commands) Missing commands and one dependency:
    - The dependency install and lock regeneration commands are not given.
    - The research-ledger check has no command.
    - pytesseract and pypdfium2's to_pil need Pillow, which is not declared or in the lock.

13. (Consistency) The high_recall CLI also writes the OOV reference, which is unrelated to thresholds. /models hardcodes 0.9627 instead of reading data/eval/llm_repeat_fireworks-deepseek.json.

14. (Tests) Missing tests:

    - per-label recall for pooled labels;
