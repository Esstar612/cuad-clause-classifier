## Findings

1. (Correctness) `build.py` does `rows = label_contract(...)` then `pd.DataFrame(rows)`. `label_contract` returns `(rows, merged)` (labels.py:93), so the frame would be built from a 2-tuple and `df["seg_idx"]` would raise. Write `rows, _ = label_contract(...)`.

2. (Correctness) Fresh contract ids. `write_predictions` enforces `contract_id: pa.int64()` (predictions.py:15, 72). The plan's `f"{contract.contract_id}_{i}"` and the EDGAR accession-based sourcing suggest string ids; the fresh `heldout`-style commands would fail at write time. Assign integer ids (for example 1000 upward, disjoint from CUAD's 0 to 509) in `contracts.parquet` with the accession and file name beside them, and build `segment_id` from the integer.

3. (Correctness, unshown glue) The `resample_weights` sketch `(contracts, stream, n=None, stratify=True)` drops `n_resamples` and `seed`. evaluate.py:83 and drift.py:382 pass `n_resamples=` by keyword, so the sketch as written breaks both. Add `stratify=True` as a trailing parameter and keep the rest. The fresh path also needs its own METHOD string (evaluate.py:30-31 says "stratified by contract type").

4. (Internal consistency, determinism) The plan says "allocate runs on the capacity left after exclusions" and that `draw` and `allocate` "alternate until stable". Capacity after exclusions is only known by checking a candidate (a document fetch and an EFTS query each), but `draw` stops a type as soon as its slots fill, so exclusion-adjusted capacity is never known for unchecked candidates. If the whole frame were checked first, the alternation would be unnecessary; if checking is lazy, the alternation is unspecified and need not terminate, because the duplicate rule depends on which contracts were "drawn earlier" and that set changes between passes. Fix: draw at the initial allocation; when a type's permutation is exhausted set `capacity[t]` to its picked count; re-run `allocate`; continue each type from its saved cursor; never revisit an accepted or rejected candidate; stop when 30 are filled or `allocate` exits. The docstring `check(row) -> None` disagrees with the call `check(row, picked)`; fix it. The rest of `allocate` is sound: floors capped by capacity, remainder order with the stated tie-break, one extra slot per open type per rotation, SystemExit when nothing is open.

5. (Experimental validity, pre-registration) `containment` divides by the candidate's shingle count only. A fresh text that contains a whole CUAD contract plus more (a master agreement with the CUAD text as an exhibit) can score under 0.20, and a long duplicate of a shorter earlier pick can score under 0.50, while the reverse direction would catch both. Use the maximum of the two directions for both rules. This is a sourcing rule, so it must be fixed before the first fetch.

6. (Correctness of the text) `BLOCK` lacks `td` and `th`, so cells in one table row concatenate with no separator ("Name" directly followed by "Address"), changing words, shingles, segment boundaries and what the labeler reads. EDGAR exhibits use tables for signature blocks, defined terms and section layouts. Add `td`, `th`, `dd`, `dt`, `blockquote`, `pre`, `ul`, `ol`, `hr` as separators (a newline is fine; the line normalisation collapses extras). Also state the conversion for plain-text exhibits, which carry SGML `<PAGE>` wrappers and hard line breaks, or exclude non-HTML exhibits; the plan only defines the HTML path. Otherwise the conversion is deterministic: `str.split()` already treats `\xa0` as whitespace, `splitlines` removes `\r`, and the output has `\n` only, so code-point offsets are stable. `<br/>` fires start and end handlers and emits two newlines, which the collapse handles.

7. (Metric correctness) `span_f1` returns 0 when both lists are empty, which is the common case for a type absent from a contract; a per-type average over contracts would be dragged down by perfect agreements. Return NaN for the empty-empty case and average over defined values. `cohen_kappa` is correct for the edge cases checked (both constant and equal gives NaN; one constant gives 0); state whether it is pooled over the fresh contracts or computed per contract, since per-contract kappa on a rare type is mostly undefined.

8. (Missing refusal) `build.py` checks the checklist is complete but not that it agrees with the spans: "not present" with spans of that type, or "marked" with none, should be refused. Also require integer `start`/`end` (JSON may carry floats).

9. (Pre-registration completeness, leakage of text) The prior-appearance EFTS check has no stated behavior when the query errors, times out or rejects a long quoted phrase; define it (reject with reason `efts_error`, logged, counted in the rejection shares) before the first fetch. The rejection log is committed; it must carry reason codes and numbers only, never the searched sentence, the matched amendment phrase or any excerpt, or contract text enters the repository.

10. (Tool robustness) `selectionSpan` assumes the selection lies inside the `<pre>`; a selection elsewhere gives wrong offsets or throws at `setEnd`. Refuse when `!pre.contains(r.startContainer) || !pre.contains(r.endContainer)` or `r.collapsed`. Before enabling tagging, hash `pre.textContent` with `crypto.subtle.digest` and compare to the bundle's SHA-256, which catches HTML-parser normalisation if the text is ever inlined rather than set through `textContent`. `Range.toString` concatenates text nodes, so the function stays correct once `<mark>` elements are inserted, as long as they add no text.

No leakage otherwise: no model sees a fresh text, retrieval is train-only, `describe` is label-free, and the reviewer and user see titles and descriptions only. No pre-registered rule changes; the Step 9 pre-registration is new and goes into BUILD_LOG before the first EDGAR request. Resampling unit is the contract, as required. No em dashes. Commands given, not run. Core logic shown. The plan's Review record says "user choices" and "User decisions"; keep both out of the BUILD_LOG entry.

Label or legal: no new decision in 9a. The guide's contents (every occurrence, CUAD descriptions, the schema's overlap and redaction rules) are for the legally trained labeler to confirm before use in 9b; this review does not decide them.
