## Findings, by severity

**1. Correctness bugs in the proposed code**

- **a. `psi` and `js_distance` normalize `q` over the whole array** (plan:77, :83). With a 2D reference this silently gives wrong shares.
  - That forces `_psi_rows` and `_js_rows` to loop over rows in Python.
  - Normalize `q` with `axis=-1, keepdims=True` and let broadcasting handle one reference row or many.
- **b. The family threshold does not guarantee 1%** (plan:36, :162).
  - Min-p values are discrete in steps of 1/2001. Ties near the 20th-smallest value are likely, and alarming on `<=` at `np.quantile(..., 0.01)` then includes every tied batch.
  - The null p-values are also computed in-sample: each null batch counts itself. A fresh exchangeable batch's p-value sits one step lower, so the realized rate edges above 1%.
  - Three places in the plan now disagree: "1% by construction" (plan:36), the test's "at most 1% plus one batch" (plan:171) and the run check "at most 1%" (plan:179).
  - Fix:
    - Compute null p-values leave-one-out: `(1 + #{j != i: null_j >= v_i}) / N`.
    - Set the family threshold to the largest attained score whose null share at `<=` is at most 1%.
    - Report the exact null rate.
    - Use one statement of the guarantee throughout.

**2. Leakage.** None found. Thresholds, bin edges and nulls come from validation only, and the vectorizer was fit on train. `calibrate` does need a test proving it never opens test or shift files (see item 10).

**3. Experimental validity**

- **a. 500 resamples cannot support a 99.375% interval** (plan:43). Each tail holds 0.3125%, which is about 1.6 resamples, so the primary rule would rest on one or two draws.
  - Step 4b rejected the same problem at 2,000 resamples for a 99.583% level (BUILD_LOG:2246).
  - This needs your decision (see below).
- **b. Validation and test are knowably not exchangeable for the model families.**
  - Rule B thresholds were tuned on validation, so the predicted label mix and none share there are in-sample.
  - Validation includes the 23 prompt-iteration contracts (BUILD_LOG:2171).
  - The null reference has 92 contracts, but the evaluation reference has 97.
  - The reading rule is robust to this because it compares shift with test, not with 1%. The pre-registration should still name these reasons before any number exists.
- **c. The pooled Spearman correlation (optional).** Pooling test and shift batches mostly re-measures the known test versus shift gap. Adding within-set correlations would be more informative. It is descriptive either way.

**4. Pre-registration**

- **a. No action is fixed for a failed null check.** Say what happens if `calibrate` shows a family above its target, for example "fix the code, not the rule", before `calibrate` runs.
- **b. Validation versus test differences.** State the item 3b reasons in the pre-registration.

**5. Internal consistency.** Covered in 1b.

**6. Dropped requests.** None. The 4b r3 review had no required changes. Its optional note on a report test applies again here (item 10).

**7. CLAUDE.md rules**

- **a. Core logic not shown.** Missing: `_hist` (how out-of-range lengths are handled), `CONF_EDGES`, `_psi_rows` and `_js_rows`, `calibrate`, `evaluate` and `drift_tables`. Within `evaluate`:
  - how a set's batches are placed into the 221 columns;

  - the 8-cell rule outcome.
- **b. Undeclared scipy import.** `scipy.sparse` is imported directly. scipy is only in the lock file (requirements.txt:42), not in pyproject.toml, and no module in `src` imports it today. Add it to pyproject.toml and give the lock regeneration command.
- **c. Attribution in BUILD_LOG.** The plan's "Decided 2026-09-27 (AskUserQuestion)" wording must not carry over into BUILD_LOG.
- No em dashes found. All commands are left for you to run.

**8. Runtime, memory and determinism**

- **a. The three-operand einsum is slow.** Without `optimize` it loops b x i x j. At 500 x 200 bootstrap rows x 221², that is about 5e9 operations per call, three calls per set. It becomes impractical if resamples go up.
  - Use `((W @ gram) * W).sum(1)`.
  - Compute `rr` once in `evaluate`.
  - Process the bootstrap in chunks: a 10,000 x 200 x 221 float64 W is about 3.5 GB.
- **b. Zero denominators.** A batch with no predicted positives or no parsed segments gives NaN. `searchsorted` places NaN at the top, which turns it into an alarm. State and test a NaN policy.
- **c. Version check.** "Refuses if any model version differs" is ambiguous. The LLM version tags include the served-model string (run.py:513-517), so a real difference between validation and held-out tags would block `evaluate`. Say exactly what is compared, and before the pre-registration give a read-only command that prints `model_version` per file.
