## Findings

1. (Correctness, unshown glue) `compare` reads `r.start`, `r.end`, `r.exclude` and `r.proba` from `stored.itertuples()`. The prediction parquet also carries `contract_id`, `split`, `start` and `end` (predictions.py:14-18). A `segments.merge(pred, on="segment_id")` would rename the collisions to `start_x`/`start_y` and `r.start` would raise `AttributeError`. The plan must state the join as merging only `pred[["segment_id", "proba"]]` left onto the segment rows. Also, if a non-excluded row ever lacked a stored proba (NaN after a left join), `np.vstack` would fail on a shape mismatch, not with a readable message; add an explicit refusal before the stack. Both belong in the shown core logic.

2. (Internal consistency) Pre-registration says expected flags are the stored probabilities "with the image's thresholds applied". The script runs locally and cannot read the image's threshold files; it applies the local ones (`models/baseline/thresholds.json`, the candidate's `thresholds.json`, and `models/service/*_thresholds_high_recall.json`). The next sentence ("a divergent high-recall file in the image would show as disagreements") only makes sense under local thresholds, so the first sentence is stale. Say "the local threshold files", and build them through `infer.artifacts(name)` and `infer._thresholds(name, art)` so the script uses the same code path as the service. Note for the record: the Rule B files are covered by the version hashes (baseline.py:139-143, transformer.py:173-182); the high-recall files are not, which is why that divergence can only surface as disagreements.

No leakage: validation contracts only, test and shift text never sent, nothing tuned. No pre-registered rule changed; the Step 8 parity rule is new and goes into BUILD_LOG before any deployed number. The resampling unit question does not arise (no interval is claimed). No label or legal question: the front end reuses the existing notices and makes no new statement about what a clause type means.
