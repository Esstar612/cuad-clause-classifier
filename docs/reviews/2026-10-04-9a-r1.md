## Findings

1. (Experimental validity, reproducibility) The sampling frame is not defined. "Full-text search or the quarterly form indexes" is undecided; EDGAR full-text search caps results at 10,000 per query and its results change as filings arrive, so a draw from a live query is not reproducible. Required: pick one method; define filing-date range, form types, exhibit types (EX-10*), and the per-type keyword lists; save the full candidate listing with its listing date to data/fresh/candidates.parquet (committed, metadata only); draw from the sorted snapshot. Record the share of EX-10 exhibits matching no type, since the frame is "exhibits with a classifiable description", which is a selection on titling.

2. (Experimental validity) The allocation rule is incomplete. By my count from contract_splits.csv (test: Strategic Alliance 7, License 7, Maintenance 7, Sponsorship 6, Development 6, Distributor 6, Service 5, Endorsement 5, Co-Branding 5, Collaboration/Cooperation 5, Hosting 4, Joint Venture 4, Outsourcing 4, Marketing 4, IP 4, Manufacturing 3, Reseller 3, Supply 3, Agency 2, Promotion 2, Affiliate 2, Consulting 2; total 96), largest remainder over 30 slots gives 8 types two slots and 14 types one slot, and the four types with 5 contracts tie for the last two slots. Required: a deterministic tie-break and a rule for a type with fewer eligible candidates than slots (several CUAD types are rare in modern EX-10 filings). Verify the counts with: python -c "import pandas as pd; s=pd.read_csv('data/splits/contract_splits.csv'); print(s[s.split=='test'].contract_type.value_counts())".

3. (Experimental validity, selection bias) "anything matching a CUAD title" would exclude fresh contracts with generic titles (DISTRIBUTOR AGREEMENT) and bias toward unusual ones, while missing re-filed CUAD contracts under new titles. Replace with a text-overlap check against the 510 local CUAD texts (shingle containment, threshold pre-registered). Make the other exclusions numeric before any fetch: redaction-marker share per 1,000 characters; blank-party markers for forms; an amendment regex that excludes "Amendment No." and keeps "Amended and Restated". Add a within-frame duplicate check (the same contract filed with two forms or by both parties). Any manual check is done by the user on the first page only and logged.

4. (Experimental validity, the contamination claim) "filed in 2026, after the LLMs' training data" is asserted, not recorded. Record each frozen model's published training cutoff (claude-sonnet-5, gemini-3.8-flash, deepseek-v4p1-flash) from provider pages, with the page date, and require filing dates after the latest. A 2026 filing can also be a re-filing: add a prior-appearance check per drawn contract (EDGAR full-text search for one distinctive sentence, dated before the frame start) and record the agreement's own date. Served model identity is already recorded by cmd_heldout (served_models), which the fresh command should keep.

5. (Reproducibility) Labels are character offsets into a converted text, so the conversion must be reproducible or the labels are unusable. Pin the HTML-to-text method (stdlib html.parser, or a library added to pyproject.toml with the lock regenerated), store a SHA-256 of each gold text in contracts.parquet, write it into every label export, and have build.py refuse a mismatch. Exclude PDF-only exhibits and log them. Add data/fresh/text/ and data/processed/fresh_segments.parquet to .gitignore.

6. (Correctness, labeler) Browser selections give UTF-16 code-unit offsets; the export promises code points. Show the conversion, render the text whitespace-exact (white-space: pre-wrap over the raw string, offsets by walking text nodes), test with astral characters and CRLF, restrict the category picker to the fixed list, and have build.py refuse unknown categories and out-of-range offsets (evaluate.indicator raises a bare KeyError on an unknown label, evaluate.py:45).

7. (Labels comparable to CUAD, annotator bias) CUAD marks every occurrence (spans per pair median 1, max 55, BUILD_LOG 128) with clause-length spans; a section-level highlight would label more segments through the 0.5-of-segment rule than CUAD's convention. The guide must say "mark every instance" and give per-category span-length guidance computed from train spans only (spans.parquet joined to splits, train rows). The guide must not mention any model's behavior: the Step 4a cases in docs/labeling_schema.md quote baseline probabilities and must not reach the annotator.

8. (Experimental validity, resampling unit) With 14 singleton types among 30 contracts, resample_weights' stratification pins 14 contracts in every resample and the interval is too narrow (BUILD_LOG 983 accepted one singleton among 97; here it is half the set). Pre-register unstratified contract resampling for the fresh set (pass a constant contract_type to resample_weights, or add a parameter), unless the user prefers coarse strata. The fresh scope rule (N fresh contracts per label) must be fixed before any label exists; it is label-free in form, so fix it now.

9. (Internal consistency, verification) The verification command cannot check segments.parquet (gitignored). Compare its SHA-256 to models/drift/reference.json["input_hashes"]["segments.parquet"] instead. Add a label-free descriptive check after sourcing: fresh segment count and length distribution per contract next to CUAD test's, since the HTML conversion gives a different line structure from CUAD's PDF-derived text (segment.py unwraps hard-wrapped lines and splits on blank lines), and a shift in segmentation would confound "newness".

10. (Evaluation discipline) "open the tool locally to try it on one contract" should use a CUAD train contract, so no fresh body is read by anyone before labeling and no stray fresh label exists. The builder reads titles and descriptions only; every rule is fixed and committed before the first fetch.
