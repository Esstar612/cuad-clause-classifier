## Findings
1. (Validity of the record) Stderr is not captured. SystemExit messages and crash tracebacks go to stderr, and "| tee" captures stdout only. With ";" the next run starts at once, so the crash-versus-failure evidence the user must decide on exists only in terminal scrollback. Use "2>&1 | tee".
2. (User requirement not verified) The plan checks the six JSON files byte-for-byte but never shows that the report's 4b and 6a tables are unchanged, or that no sensitivity table appears for them. Add a test and a pasted git diff of results_tables.md.
3. (Missing test) The one-failed-run validate test must leave a pre-failure checkpoint on disk, or it cannot show that such checkpoints are excluded.
