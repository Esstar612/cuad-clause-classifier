## Findings
1. (Correctness, verification) Startup guards do not fail the container (above). Add a strict mode read in `service_settings` (for example `SERVICE_REQUIRE_ALL_MODELS=1`, set in the image) under which lifespan raises when `failed` is non-empty; and have `deploy_parity.py` compare the versions the service reports to the local `baseline.model_version()` and `selected.json["model_version"]`, failing on mismatch. Tests for both. Rewrite the Verification bullet.
2. (Correctness, Dockerfile) `pip install --no-deps .` installs a second, non-editable copy of `src` and `service` into site-packages. `config.ROOT_DIR = Path(__file__).resolve().parent.parent` (config.py 9) then resolves to site-packages, and MODELS_DIR, EVAL_DIR, SERVICE_DIR all point at nothing. It works today only because uvicorn's default `--app-dir .` puts the working directory first on `sys.path`; any other entry point (a `python -m` command inside the container, gunicorn) loads the broken copy. Use `WORKDIR /app` with `ENV PYTHONPATH=/app`, or an editable install.
3. (Correctness, parity script) segments.parquet keeps excluded segments (`exclude` true when a segment's only clause labels are rare-dropped ones, labels.py 72 to 76); `load_segments` drops them (build_segments.py 42 to 43) before any model predicts, so `baseline_val.parquet` and `transformer-tuned_val.parquet` have no row for them (5 in validation, BUILD_LOG 470). The service will return those segments. The plan must say: match against all segments.parquet rows of the contract, skip excluded ones in the comparison, report the skipped count.
4. (Experimental validity, pre-registration content) Pass rule denominator. 11,656 validation segments over 97 contracts gives about 2,400 segments and 79,000 (segment, label) pairs for 20 contracts; 0.1% is about 79 flips. Flagged pairs in that sample will be a few hundred at the balanced point (about 11% of segments carry a label in train, baseline search log BUILD_LOG 499), so the rule can pass a deployment that disagrees on a fifth of its flags. User decision: (A) keep 0.1% of all pairs and add at most 1% of pairs flagged by either side; (B) the flagged-union rule alone. Recommend A. For the baseline, 0 is a sound rule, but the rationale "any difference means a different artifact or library" overstates it: arm64 and x86_64 BLAS can differ in the last bits, and a flip needs a probability within rounding of a 0.01 grid value. Say "a nonzero count is investigated, not excused".
5. (Security, public endpoint) `ClassifyRequest.text` has no size limit and Cloud Run accepts 32 MiB bodies; `Predictor.scores` holds a lock (infer.py 61 to 63), so one huge body occupies the single instance for the whole timeout and queues everyone else. Add `SERVICE_MAX_TEXT_CHARS` (the longest CUAD contract is about 338k characters; 1,000,000 leaves room) returning 413 for pasted text and for extracted PDF text; test it. Run as a non-root `USER` in the Dockerfile, since pypdf, pdfium and Tesseract parse untrusted bytes. CORS: allow only `Content-Type`, GET and POST, no credentials. Record in BUILD_LOG that the budget alert notifies and does not stop spend; the hard bound is one instance.
6. (Build failure mode) Add `--only-binary=:all:` (and `--no-cache-dir`) to both pip installs. Every pin needs a manylinux cp314 wheel (sentencepiece 0.2.2, tokenizers, safetensors, hf-xet, pypdfium2, pyarrow 25, scikit-learn 1.9.1, scipy 1.18.1, pandas 3.0.6); on `python:3.14-slim` a missing wheel means a long source build that fails for lack of a compiler. Failing fast names the package. Give the exact torch command: `pip install --only-binary=:all: torch==2.14.0 --index-url https://download.pytorch.org/whl/cpu`.
7. (LLM behavior, latency) CPU throughput of legal-BERT on 2 vCPU is unmeasured (Step 6 latencies are MPS). The longest validation contracts run to several hundred segments at up to 512 tokens; `--timeout 300` may cut them. Use 900 or more, give `deploy_parity.py` an httpx timeout at least that long, and record a timeout as a failed request with the contract id. Memory: `TRANSFORMER_INFER_BATCH` 64 at 512 tokens produces attention tensors of about 800 MB per layer in float32 on top of the 440 MB model; 4 GiB likely holds but is not comfortable. Consider 8 GiB, or measure peak RSS locally first.
8. (CLAUDE.md) The parity sampling and metric code is core logic (sampling, metrics); the plan should say it will be shown before placement.
